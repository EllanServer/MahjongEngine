# 国标麻将玩家规则

[English](./gb-mahjong-rules.md) · [日本語](./ja-JP/rules/gb.md)

> **规范基线：** `GB` 预设以 EMA/WMO《麻将竞赛规则》（Green Book）为裁决依据。vendored [`GB-Mahjong`](https://github.com/zheng-fan/GB-Mahjong) 只是实现依赖，不是与规则书并列的裁判来源；显式改动通用牌桌选项后属于兼容房规，不再是严格 MCR 赛程。

## 快速查表

| 项目 | 当前插件规则 |
| --- | --- |
| 人数 | 固定 4 人 |
| 牌数 | 144 张，包含全部 8 张花牌 |
| 牌墙 | 全部可摸，没有日麻 14 张王牌区 |
| 起手 | 补花前庄家 14 张，其余玩家 13 张 |
| 比赛账本 | 严格预设从净分 0 开始；没有目标分终止条件 |
| 起和门槛 | 至少 8 番，花牌番不计入门槛 |
| 动作 | 吃、碰、大明杠、暗杠、加杠、荣和、自摸 |
| 截和 | 单响 |
| 赛长 | `GB` 预设为东一至北四 16 手；牌桌规则可改赛长；不连庄 |

## 1. 牌组与花牌

完整 144 张牌包括：

- 108 张序数牌：万、筒、索各 1 至 9，每种四张；
- 16 张风牌：东、南、西、北各四张；
- 12 张箭牌：白、发、中各四张；
- 8 张单例花牌：梅、兰、竹、菊、春、夏、秋、冬。

起手或摸到花牌时，玩家可以点击 **“亮花”** 公开补花并从牌墙尾端补一张，也可以保留，之后把它作为弃牌打出。补花取得的仍是花牌时再次选择。只有已经公开的花牌参与花牌番；未公开花牌不能组成和牌牌型。弃出的花牌不能被吃、碰、杠或用来和牌。

## 2. 掷骰、开门与发牌

开局分两次、每次掷两枚六面骰。第一次点数和从庄家起决定开门边，两次点数和共同决定该边的断点。144 张牌全部属于同一可消耗牌墙，没有立直麻将的王牌与宝牌保留区。

发牌顺序为：

1. 东、南、西、北依次每人取得四张，重复三轮；
2. 四家各再取得一张；
3. 庄家跳牌取得第十四张；
4. 原始牌保持在各家手中；数字牌桌在该玩家自己的回合提供“补花”或保留后弃出的选择，不强制公开。

普通摸牌从牌墙前端进行；补花和杠后补牌从牌墙尾端进行。

## 3. 行牌与合法动作

普通回合摸一张、打一张。满足条件时可进行：

- **吃：** 只有出牌者的下家可以用该牌组成顺子。
- **碰：** 任一对手可以用该牌组成刻子。
- **大明杠：** 任一对手可以用该牌组成明杠，随后从尾端补牌。
- **暗杠：** 自己回合用四张相同手牌成杠并补牌。
- **加杠：** 向已有的碰补入第四张；成立前可能被抢杠。
- **荣和：** 用别人打出的牌和牌。
- **自摸：** 用自己摸到的牌和牌。

反应优先级为“荣和 > 碰 / 大明杠 > 吃”。同一张弃牌有多人荣和时，本 profile 只结算一名荣家，不使用多家荣和；同优先级竞争由行牌顺序更近的合法玩家取得。

`GB` 没有立直、一发、振听、表宝、里宝、赤宝、本场棒或立直棒。

## 4. 和牌与 8 番门槛

原生后端负责牌型合法性、听牌、番种组合与总番，不另维护一套 Java 计番克隆。

和牌必须先达到至少 **8 番非花牌番**。花牌番可以增加最终支付，但不能把原本不足 8 番的手牌抬过起和门槛。

听牌显示也遵守这个区别：如果牌型本身 7 番，而自摸番能补到第 8 番，该自摸等待仍可显示为合法；只靠花牌番才能达到 8 番的牌型不能和牌。

结算界面会列出原生后端返回的番种。`MINGANGANG` 是 bridge 为规则书“一个明杠加一个暗杠共 6 分”使用的内部组合键，不是第 82 个官方番种。边张、嵌张、单钓将按形式等待判定：即使另一门等待牌四张都已耗尽，形式上仍是多面听，就不能错误加独听分。

## 5. 结算公式

令 `F` 为和牌总番。该牌必须已经在扣除花牌番后独立通过 8 番门槛；通过后，花牌番会包含在用于支付的 `F` 中。

- **自摸：** 三名对手各付 `F + 8`，和牌者共得 `3 × (F + 8)`。
- **点和：** 放铳者付 `F + 8`，另外两家各付 8，和牌者共得 `F + 24`。

所有分差按零和方式原子应用。牌墙耗尽时没有日麻式听牌 / 未听 3000 点转移。

## 6. 赛长与庄家

严格 `GB` 预设从每人净分 0 开始，并使用四圈：

- 东一至东四；
- 南一至南四；
- 西一至西四；
- 北一至北四。

未改动的 `GB` 预设严格进行 16 手，每手结束都轮庄，不连庄。MCR 不使用 500 起始分，也没有按目标分延长。通用 `startingPoints`、`minPointsToWin`、`length` 只为旧牌桌和自定义房间兼容保留；一旦修改，界面与文档都应把该桌标为房规，而不是严格国标比赛。

其他通用立直选项不会改写本 profile：8 个非花牌番门槛、单响、无赤牌、无宝牌在 `GB` 中保持固定。

## 7. 原生后端的职责边界

MahjongPaper 通过 JNI bridge 把暗手、副露、和牌张、自风 / 圈风、花牌、和牌方式和状态标记送入 vendored 原生库。原生库返回合法性、听牌、番种、总番与分差；MahjongPaper 负责反应窗口、牌墙流程、玩家提示、结算界面、历史记录和分差的原子应用。

这意味着：

- 国标计番不应悄悄漂移到无关的本地房规实现；
- 使用原生库也不能据此宣称与所有 MCR 修订版、所有现场裁判判例完全一致。

排查边界牌例时，应同时核对 MahjongPaper 送出的精确请求、vendored 后端结果和外部规则文本。

## 8. 本项目 profile 的重点差异

很多“麻将入门”视频讲的是地方麻将或家庭规则，不一定是国标。不要把王牌、立直、宝牌、连庄、多家荣和或另一套结算公式带入本模式。

当前 `GB` 对玩家的明确承诺是：

- 使用 144 张牌和全部八花；
- 8 番门槛只统计非花牌番；
- 采用上文“8 + 番数”结算；
- 单响；
- 严格预设从净分 0 开始并固定 16 手，不连庄；
- 番种解释来自 bundled vendored 后端，但不承诺覆盖每个官方赛事边界。

## 10. 实现与回归契约

本页是当前插件 profile 的规范性玩家规则。规则变更只有在控制器 / 原生映射、中英日三语文档和保护该行为的测试同步更新后才算完成。

- 核心实现：`GbTableRoundController.java`、`GbRoundSupport.java`、`GbReactionResolver.java`、`GbRuleProfile.java`、`native/gbmahjong/src/gbmahjong_jni.cpp`。
- 主要回归契约：`GbOfficialRulesRegressionTest`、`GbTableRoundControllerTest`、`GbReactionResolverTest`、`GbMahjongRealWorldFanCoverageTest`、`SessionRulePresetResolverTest`。
- 必守不变量：144 张且包含全部八花、补花可选；扣除花牌番后达到 8 番才能和；采用“8 + 番数”结算；单响；始终不连庄；严格 `GB` 为净分 0、固定 16 手。
- 原生边界不变量：vendored 后端若与 Green Book 冲突，应修正后端与测试；后端本身不是规则权威。
