# 国標麻雀（中国競技麻雀 / GB）

[日本語ドキュメント](../README.md) | [インストール](../installation.md) | [リーチ麻雀](./riichi.md) | **国標麻雀** | [四川麻雀](./sichuan.md)

`GB` は EMA/WMO Green Book を規範とする中国競技麻雀（Mahjong Competition Rules / MCR）モードです。vendored `GB-Mahjong` は牌姿解析と fan 計算の実装依存であり、規則書に優先する裁定元ではありません。

> [!WARNING]
> 外部の動画・教本・実卓大会は、MCR の版、会場運用、時間制限、罰則、裁定、または地域 house rule が異なる場合があります。**ゲーム内の最終動作は、このページの「MahjongPaper profile」を基準にしてください。** 外部教材へのリンクは学習用であり、提携・承認を意味しません。

## MahjongPaper profile

| 項目 | 現在の動作 |
| --- | --- |
| モード | `GB` |
| 牌 | 萬・筒・索、風牌、三元牌、花牌の計 144 枚 |
| 得点帳 | 厳格 preset は各 0 点からの純増減 |
| 試合長 | 東南西北の四圏、固定 16 局 |
| 連荘 | なし |
| 和了条件 | 花牌分を除いて 8 fan 以上 |
| ロン | 一人だけ |
| ルール評価 | bundled `GB-Mahjong` JNI bridge |

このモードは、曖昧な「中国麻雀風」ではありません。実行時の牌姿・fan 評価は native backend へ構造化 request を渡して行いますが、規範は Green Book です。backend と規則書が食い違う場合は、backend または mapping と回帰テストを規則書側へ修正します。

## 牌と牌山

144 枚すべてを使用します。

- 萬子・筒子・索子
- 東・南・西・北
- 白・發・中
- 花牌

物理的な牌山表示では、各辺 36 枚です。リーチ麻雀のような固定 14 枚の王牌はありません。

- 通常摸牌：牌山の前側
- 補花・槓後の補充牌：牌山の後ろ側
- 144 枚はすべて同じ活牌山の消費対象

赤牌は使用しません。

## サイコロと開門

開局時は、六面サイコロを二個ずつ、合計二回振ります。

1. 一回目の合計を、親から反時計回りに数えて開門する辺を決めます。
2. 二回目の合計も使い、開門位置の幢数を決めます。
3. controller、session、物理牌山表示は、同じ開門結果を使用します。

画面上の演出だけ別の位置から配ることはありません。四人のどの席が親でも、2～12 のサイコロ結果を同じ規則で解釈します。

## 配牌と補花

初期配牌は、実卓の競技手順を意識した順番です。

1. 東家から順に、各プレイヤーへ 4 枚ずつ配ります。
2. これを三回行い、各 12 枚にします。
3. 東・南・西・北へ各 1 枚を配ります。
4. 親は跳牌で 14 枚目を取得します。
5. 花牌は強制公開しません。持ち主の手番で **「花牌公開」** を選んで牌山後方から補充するか、保持して後で捨てるかを選べます。
6. 補充牌も花牌なら、同じ選択をもう一度行います。

捨てられた花牌をチー・ポン・槓・和了に使用することはできません。公開済みの花牌だけが花牌 fan に入り、保持中または捨てた花牌は和了形を構成しません。

補花の公開順が、各プレイヤーの初期配牌を途中で割り込むことはありません。

## 手番と鳴き

- 通常は摸牌してから 1 枚捨てます。
- チーは捨てたプレイヤーの次順だけが可能です。
- ポンと明槓は、条件を満たす他家が申告できます。
- 暗槓、加槓、明槓の後は牌山後方から補充します。
- 加槓には搶槓ロンの反応機会があります。

同じ捨て牌へ複数の反応がある場合：

```text
和了 > ポン / 明槓 > チー
```

ポンと明槓は同じ優先度で、捨てたプレイヤーから手番順で近い申告者を選びます。

## 8 fan の和了条件

完成形であっても、花牌を除く fan が 8 未満なら和了できません。

- 花牌以外で 8 fan 以上：和了可能
- 花牌以外で 7 fan、花牌 1 fan：和了不可
- 花牌以外で 8 fan、花牌 2 fan：和了可能。支払い計算には花牌分も加える

つまり、花牌は成立済みの和了価値を増やしますが、8 fan の最低条件を満たすためには使えません。

例：

```text
混一色 6 fan + 碰碰和 6 fan = 12 fan → 和了可能
碰碰和 6 fan のみ = 6 fan → 和了不可
```

native backend は、fan の重複排除や包含関係を含む内訳を返します。内部キー `MINGANGANG` は「明槓一組＋暗槓一組＝6点」を表す bridge 上の合成結果で、82番目の公式 fan ではありません。形式上の多面待ちは、別待ちがすでに四枚見えていても辺張・嵌張・単釣将を加算しません。

## 点数計算

未変更の `GB` preset は各プレイヤーの純得点 0 から開始し、合計 0 を維持します。MCR に 500 点の初期オフセットや目標点延長はありません。汎用の `startingPoints`、`minPointsToWin`、`length` を変更した卓は互換 house rule として扱います。

### ツモ

他の三人が、それぞれ次を支払います。

```text
支払い = 成立 fan + 8
```

### ロン

- 放銃者：`成立 fan + 8`
- 放銃者以外の二人：各 8

すべての差分は一つの原子的なゼロサム更新として適用し、合計点を増減させません。

## 一人ロン

国標モードは、一つの捨て牌に対して一人だけが和了する profile です。複数人が和了可能でも、捨てたプレイヤーから手番順で最も近い合法な和了者を選びます。

リーチ麻雀の `MULTI_RON` 設定を国標へ持ち込みません。

## 既定の試合長と順位

- 東一局から東四局
- 南一局から南四局
- 西一局から西四局
- 北一局から北四局

未変更の `GB` preset は計 16 局で、各局後に必ず親を交代し、目標点による延長を行いません。汎用設定を変えた短局・オフセット卓は、厳格 MCR ではなくカスタムルームです。

リーチ用の他の共通設定は、この profile を書き換えません。花牌を除く 8 fan 条件、一人ロン、赤牌なし、ドラなしは `GB` で固定です。

国標の結果画面は国標の raw point を使用し、リーチ麻雀の雀魂風得点式を重ねません。現在、対局結果から段位と統計を自動更新するのは 4 人の人間プレイヤーによる `RIICHI` だけです。`GB` の対局は leaderboard 投影を更新せず、`/mahjong leaderboard GB` は既存または移行済みデータを参照するだけです。

## native backend と検証境界

MahjongPaper が native backend に任せる範囲：

- 手牌 request の解析
- fan 計算
- 聴牌候補
- fan 内訳
- 合法な和了候補

MahjongPaper が担当する範囲：

- サイコロ、開門、配牌、補花
- 手番、鳴き、反応優先度
- 点数差分と結果画面
- プレイヤー案内、音声、履歴、永続化

自動テストは native fan/ting/win entry point と卓進行の主要境界を検証します。backend と Green Book が食い違う場合は、backend、bridge、テストを規則書側へ修正します。

| ツモ | `/mahjong tsumo` |
| ロン | `/mahjong ron` |
| チー | `/mahjong chii <tileA> <tileB>` |
| ポン | `/mahjong pon` |
